# 知识页面与首页卡片创作规范

这份说明用于让后续作者和 AI 工作流延续 BigGhost AI Notes 的内容表达与视觉风格。它是项目内的创作依据，既可以直接阅读，也可以在未来任务中明确引用。

## 1. 从哪里开始

| 文件 | 用途 |
| --- | --- |
| [AGENTS.md](../AGENTS.md) | 支持此约定的代码助手在项目中工作的入口说明 |
| [首页](../site/index.html) | 品牌、首页布局、卡片与深浅色实现的基准 |
| [现有笔记](../site/notes/compatibility-layers/index.html) | 长篇知识讲解、框架图、案例切换与打印效果的基准 |
| [部署指引](../DEPLOYMENT.md) | 本地预览、同步 GitHub 与发布网站 |

当前网站只发布 `site/`。每篇文章的位置为 `site/notes/<slug>/index.html`，`slug` 使用简短、稳定的小写英文和连字符。已分享过的路径尽量保持不变。

首页上的“选项卡”实际上是**进入笔记的链接卡片**。沿用现有链接结构，不要为它额外制造页签切换逻辑。

## 2. 内容表达：让读者建立理解

### 一篇文章的组织方式

根据问题选择需要的部分，常用顺序是：

1. **首屏提出问题。** 标题短而清楚，简介说明本文解释什么。首屏配一张有意义的概念图。
2. **给出最有用的结论。** 先建立读者能够带着往下看的基本判断。
3. **展示全貌。** 用分层图、流程图、关系图或对照图解释概念之间的关系。
4. **按需展开。** 每节解决一个问题，术语首次出现时给中文解释，再补必要英文名。
5. **放入具体例子。** 用“发生了什么 → 为什么 → 怎样处理 → 什么情况下不成立”讲清因果。
6. **解释边界与误区。** 需要限定的结论写清前提，较深入内容可以收进折叠区。
7. **给出来源。** 引用指向能够支持具体结论的原始材料，注明用途和需要的日期信息。

不要求每篇文章都拥有分层选择器、六个案例或二十多个来源。图和交互要服务于主题；短问题可以用短页面解释完整。

### 文案与资料

- 使用简体中文、具体动词和短段落。先解释日常含义，再进入专业细节；类比之后补一句它适用到哪里。
- 图中的连线要有明确意义，例如调用、数据流或依赖。装饰图不能被当作精确架构证据。
- 平台支持、软件版本和性能等易变结论重新查证。不要沿用上一笔记的 `2026.09.13` 作为新笔记的核查日期。
- 来源尽量采用官方文档、论文与项目原始说明。能用一份准确来源支撑的结论，不通过堆积引用制造可信感。
- 展示真实的首次发布日期；修改时间、资料核查时间在有必要时另行标注。
- 不把提示词或协作过程带进页面，如“已按你的要求整理”“主线约 5 分钟”“面向非技术读者”。侧栏写主题说明，例如“理解兼容性的边界”，然后用一两句交代研究对象。
- 避免没有内容的章节、空列表项、占位卡片、虚构的统计数量和未经估算的阅读时长。

## 3. 视觉基准

整体气质是清晰、轻盈、克制的苹果风：浅灰画布、白色卡片、柔和玻璃、蓝紫渐变和充分的层级。深色模式使用深蓝灰底色。装饰集中在首屏、专题封面和少量交互状态，正文保持易读。

### 网站图标

所有知识页沿用首页的蓝紫渐变小幽灵图标。矢量原稿在 [site/favicon.svg](../site/favicon.svg)，兼容图标在 [site/favicon.ico](../site/favicon.ico)，ICO 包含 16、32、48 像素三种尺寸。

新笔记的 `<head>` 复制现有笔记的两条 `rel="icon"` 声明：第一条引用 `../../favicon.ico`，第二条是内联 SVG 的 data URL。首页的 ICO 路径为 `./favicon.ico`。不要写成 `/favicon.ico`，以免丢失 GitHub 项目站前缀。内联图标让支持它的浏览器在单独打开 HTML 时也能显示标识；旧浏览器在线访问时使用 ICO 回退，不影响离线正文阅读。

后续调整图标时，同步更新 SVG 原稿、ICO 及各页面内联数据，保持所有页面一致。无需为了网站标签图标新增 JavaScript、外部图标库或站点清单。

### 色彩

首页和笔记属于同一套视觉语言，但各自保留已有变量名与细微色差，无需为新增内容把旧页面统一重写。

| 用途 | 首页浅色 / 深色 | 参考笔记浅色 / 深色 |
| --- | --- | --- |
| 页面背景 | `--bg: #f5f5f7 / #0c0e16` | `--paper: #f5f5f7 / #080a10` |
| 卡片表面 | `--surface: #fff / #171b28` | `--surface: #fff / #141822` |
| 正文 | `--ink: #20212b / #f0f1f8` | `--ink: #1d1d1f / #f0f1f7` |
| 次要文字 | `--muted: #676b7c / #a5aabd` | `--muted: #676971 / #a1a5b5` |
| 边框 | `--line: #dedfe8 / #2c3041` | `--line: #dfe1e8 / #282d3a` |
| 紫色强调 | `--accent: #5c57d2 / #b2a4ff` | `--purple: #7455dc / #b4a0ff` |
| 链接蓝色 | 按首页现有强调色 | `--teal: #0066cc / #80b6ff` |

**参考笔记是分阶段升级的 HTML，文件开头仍有旧绿色样式。后置的苹果风覆盖和末尾间距补丁才决定当前效果。** 复用时应查看整个样式级联及浏览器结果，不要仅提取第一个 `:root`。

新增组件优先使用当前页面的颜色变量。需要醒目的警示或状态时使用现有语义色，同时提供文字或图标，避免只靠颜色传意。

### 字体、大小与布局

- 字体沿用系统栈：`-apple-system`、`BlinkMacSystemFont`、`PingFang SC`、`Microsoft YaHei`、`sans-serif`；代码用系统等宽字体。不要引入在线字体。
- 首页正文基准为 `15px / 1.8`；首屏简介 `14px / 1.95`，卡片简介 `12px / 1.95`。重要解释不要用封面英文小字的字号。
- 首页大标题使用 `clamp(42px, 5.3vw, 64px)`、约 `1.22` 行高；卡片标题使用 `clamp(23px, 2.7vw, 30px)`、约 `1.45` 行高。
- 参考笔记的首屏标题约 `44–67px`，章节标题约 `29–44px`，常规正文约 `13–15px`。长中文标题应自然换行；不要为了强行一行展示而缩得很小。
- 首页内容宽度上限 `1120px`；笔记 `.shell` 上限 `1440px`，桌面布局包含左侧目录与正文。
- 首页卡片圆角 `26px`，手机 `22px`；笔记主要容器圆角约 `20–24px`，小控件更小。沿用现有组件，不随机加入新的圆角等级。
- 边框一般 `1px`，阴影柔和。首页卡片当前阴影为 `0 24px 60px -34px #36306035`，深色使用其现有变体。
- 断点以各自页面已有实现为准：首页主要是 `900px` 和 `650px`；参考笔记另有更窄屏调整。手机端卡片改为上下结构，复杂图示改为纵向或局部横向滚动。

桌面首页卡片沿用左侧概念封面、右侧摘要，比例约 `.86fr / 1.14fr`。首屏不因为文章增加而整体换风格。

### 动效与可访问性

- 常规悬停过渡约 `0.2–0.35s`、位移约 `2–4px`；首屏浮动约 `7s`。不要加入频繁弹跳、闪烁或阻碍阅读的入场动画。
- `prefers-reduced-motion: reduce` 下停用装饰动画和平滑滚动。参考笔记的手动动效开关也要继续有效。
- 内容默认可见，再增强动效。动画脚本失败或用户关闭动效时，不应留下一片隐藏正文。
- 每页保留一个 `h1`，章节使用 `h2/h3`；保留跳转到主要内容的链接、可见键盘焦点、按钮标签和选中状态。
- 装饰图使用 `aria-hidden="true"`；承载正文含义的图需要文字说明或可访问名称。
- 深浅色通过 `html[data-theme]` 切换，存储读取使用 `try/catch`，兼容本地文件与受限浏览器。

## 4. 编写一篇独立笔记

### 文件与首屏

每篇笔记默认只有一个交付文件 `index.html`。将样式、脚本、SVG 与需要的图形内联，避免为了展示正文去 `fetch()` 同目录 JSON，也不要依赖 CDN 库。外部资料链接可以保留；断网时只是无法打开外部来源，不影响文章本身。

可参照现有笔记组织以下区域：

| 区域 | 可复用的类名 / 结构 | 使用约定 |
| --- | --- | --- |
| 顶栏 | `.topbar`、`.topinner`、`.top-actions` | 主题、动效、打印等控件按实际功能保留 |
| 目录 | `.side nav`、`.mobile-nav` | 目录条目与真实章节锚点一一对应 |
| 侧栏简介 | `.sidenote` | 简短主题介绍，不写交付过程 |
| 首屏 | `.hero-opening`、`.hero-copy`、`.eyebrow` | 问题、简介与主题相关的概念图 |
| 章节 | `section.chapter`、`.sectionhead`、`.kicker`、`.intro` | 一节围绕一个主要问题 |
| 图解 | `.map`、`.flow` 等现有模块 | 根据内容选用，连线和标签具有解释意义 |
| 案例 | `.case-select`、`.case-stage` | 仅在对比多个情况有帮助时使用 |
| 深入内容 | `details > summary + .details-body` | 原生折叠语义，打印时可读 |
| 来源 | `.sources-list`、`.source`、`.ref` | 参考编号和实际来源匹配 |

新笔记建议在顶栏提供 `href="../../index.html"` 的“知识库首页”入口。它在本地完整目录和 GitHub 项目站上都有效。单独发出笔记 HTML 时，正文仍可阅读，但相对首页入口需要配套首页文件。

参考笔记的滚动高亮脚本会扫描 `.side nav a` 和 `.mobile-nav a`，并把链接当作本页选择器。因此返回首页入口应放在顶栏等扫描范围之外；如果需要放进目录，先让脚本过滤掉非 `#anchor` 链接，避免 `querySelector` 报错。

标题、简介、主图、侧栏、章节导航、按钮名称、图例、来源说明、页尾与 `<meta name="description">` 都要适配新主题。不要留下兼容性笔记专属的 Windows/Mac 对照栏、CPU/GPU 图例或旧主题英文标签。

### 复制交互模块时的关键依赖

参考笔记不是可任意替换文字的通用模板。它同时保存了：

1. 正文中已经渲染好的初始选项和内容。
2. 底部脚本里的 `layers`、`cases`、`sources` 数据及渲染函数。
3. 打印时展示全部层次、案例的完整内容副本。

运行时并不会自动把所有静态区域重新生成。**如果只改数据数组，读者在点击前、点击后和打印时可能看到三套不同内容。** 修改时同步所有对应区域；若新主题不需要该交互，可保留视觉组件并简化为静态内容，同时去掉对应事件代码。

- 检查选择器、`data-layer` / `data-case`、`aria-controls`、预选状态和数据 ID 是否一致。
- `#layer-print` 与 `#case-print` 是完整打印副本；`theme-toggle`、`motion-toggle`、`print`、`progress` 等 ID 有对应事件绑定，修改 ID 时同步检查脚本。
- `.map .layer:last-child { grid-column: 1/-1; }` 针对原笔记的奇数项布局。新主题若有偶数项，按实际数量调整，不要让最后一项无故独占一行。
- 每篇来源编号可从 1 开始，但本页的所有 `href="#sN"` 必须指向存在的来源。同步正文来源区、脚本引用和打印内容。
- 同一页内 ID 唯一；不同 HTML 文件之间可以使用相同 ID。
- 首页目前使用 `bigghost-notes-theme`；原笔记使用 `compatibility-map-theme` 与 `compatibility-map-motion`。新笔记建议采用 `bigghost-note-<slug>-theme` / `bigghost-note-<slug>-motion`，并在首屏初始化和交互处理里一致替换。不要只改一处或顺手改掉原文章的偏好设置。
- 新增文章时无需改动原兼容性笔记的正文或脚本。

## 5. 同步首页卡片

### 卡片字段

每篇已发布笔记对应一个 `<article>`，内部是一整个 `.note-card` 链接。保留现有 `note-cover`、`note-body`、`note-meta`、`note-bottom` 等类名，复用首页样式。

| 字段 | 约定 |
| --- | --- |
| 标题 | 与笔记主题一致，不截断关键信息 |
| 简介 | 两三句话，说明读者将理解的问题和范围 |
| 类别与形式 | 真实反映内容，如“计算机基础”“交互图解”；纯静态文章不要标成互动工具 |
| 日期 | `time[datetime]` 使用 `YYYY-MM-DD`，可见文本使用 `YYYY.MM.DD` |
| 标签 | 选少量核心术语，默认约 2–4 个 |
| 编号 | 当前首篇为 `001`，新篇可按创建顺序继续编号；排序变化不要求改旧编号 |
| 封面 | 延续深蓝背景与蓝紫概念图，但图形和文字对应新主题 |
| 链接 | `notes/<slug>/index.html`，点击卡片即可进入文章 |

默认新文章放在列表前面，原文章继续保留。首页首屏的纸张图目前是首篇主题的装饰，不是总数显示；不要为了新增一篇文章自动更改它或重写首屏文案。

## 6. 空白与溢出：保留已经修好的体验

合理的章节留白需要保留，但列表末尾、折叠项下方和来源末尾不应出现像“空了一行”的多余区域。

检查顺序：先找空 `p/li/div`、结尾 `<br>`，再看最后一个元素的 `margin-bottom`、容器 `padding-bottom`、固定高度或 `min-height`，最后看网格是否把短内容拉伸到相邻长内容的高度。源码中的正常缩进和换行通常不会产生可见空行，无需压缩所有 HTML。

参考笔记末尾已有以下局部修复；复用这套章节结构时应保留或等效处理：

```css
@media screen {
  section.chapter { padding-bottom: 24px !important; }
  section.chapter > :last-child { margin-bottom: 0; }
  section.chapter:has(> details:last-child),
  section#sources.chapter { padding-bottom: 0 !important; }
  section.chapter > details:last-child { border-bottom: 0; }
  .glossary { align-items: start; }
  #sources .sources-list { margin-top: 12px; }
}
```

这组规则有特定结构前提：不应机械地把所有新容器的底部间距都设为零。尤其不要全局删除列表、段落的正常间距来掩盖单个组件的问题。

这组补丁放在原有响应式规则之后，避免被旧间距覆盖。来源章节若改了 ID，应同步 `#sources` 选择器。移动端 `.layer-detail` 的最终 `min-height` 为 `0`，不要恢复基础样式中的固定最小高度，让短说明下方再次出现大块空白。

首页曾因光晕负边距和旋转轨道超出屏幕而出现手机横向滚动，移动样式已收紧 `.hero-art::before` 和 `.orbital`。后续变更装饰时也要检查其真实边界；不要用整页 `overflow-x: hidden` 把正文一起裁掉。

## 7. 每次新增的工作流

1. 阅读本说明和两个参考页面，检查 Git 工作区。确定新文章的主题、核心问题、目录名和范围。
2. 收集需要的资料并先形成大纲，选定真正有帮助的图示与交互。
3. 在新目录内完成自包含 HTML，适配首屏、目录、正文、来源、深色、手机和打印。
4. 同步首页卡片、唯一 ID、真实元信息和两处总数；不要提前加入尚不存在的页面。
5. 本地预览并完成下方检查，再按当前任务授权提交和推送。发布方法见 [DEPLOYMENT.md](../DEPLOYMENT.md)。

### 最小完成检查

- 首页卡片可进入正确笔记；新笔记可返回首页；标题、日期、摘要、编号和总数相符。
- 本地双击 HTML 后正文和图示能阅读，没有依赖运行服务器才能加载的内容。单独发送的文件能够独立阅读正文。
- 320px、390px 手机和普通桌面宽度下可读、无整页横向溢出；表格如需滚动，仅自身容器滚动。
- 深浅色均能辨认正文、标签和图例；键盘可操作链接、按钮和折叠项，焦点可见。
- 尊重减少动态效果；关闭动效时内容仍完整。涉及交互变更时检查实际切换和脚本错误。
- 打印能包含交互中隐藏的必要内容；未选中的案例、折叠说明和来源没有被遗漏。
- 没有重复 ID、缺失的锚点、空列表项、模板占位符、上一主题的残留文字或明显冗余空白。
- 对改动执行 `git diff --check`。纯文档修改只核对说明与链接，不必重新进行全部页面检查。
